## 1. What is this project?

A full-stack **school fee-management system** (a.k.a. School Management System):

| Layer | Tech |
|-------|------|
| Backend | **FastAPI + SQLAlchemy 2.0 (async) + Alembic + PostgreSQL (Neon)** |
| Frontend (main) | **React 18 + Vite + Tailwind CSS + axios + react-router-dom + recharts** |
| Extra | RSA-encrypted CNIC/B-Form fields, JWT auth (cookie-based), slowapi rate limiting |

Feature scope: students, parents, teachers, fee types (+ per-class overrides), monthly invoices (one per student per month), payments, users/roles (admin/staff), and a dashboard with real monthly-collection charts.

**Key design decisions** (from `school-backend/app/models.py`):
- One invoice per student per month; `invoice_line_items` holds the per-fee breakdown
- Invoice status auto-derived: `pending / partial / paid / overdue`
- Siblings are derived from shared parents (no extra table)
- Balance is always derived: `total_amount − SUM(payments)`
- CNIC/B-Form is RSA-OAEP encrypted at rest; a SHA-256 hash column is kept for uniqueness (since RSA is randomized)

## 3. Running the servers — start / stop / restart guide

> ⚠️ **Current state:** as of this session, both servers are **already running** —
> backend at `http://localhost:8000`, frontend at `http://localhost:5173`.

Environment used: Linux, Python 3.12.3, Node v24.12.0, npm 11.17.0, Docker (Postgres 16 on port 5433).

### 3.1 One-time setup (fresh machine)
```bash
# ── Backend ────────────────────────────────────────────────
cd school-backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# ⚠ REQUIRED (blocker): pin bcrypt back — see Problem #1
.venv/bin/pip install 'bcrypt==4.0.1'

# ⚠ REQUIRED: create .env from .env.example with a real Postgres URL,
#   SECRET_KEY (openssl rand -hex 32) and RSA keys (see .env.example for how).
#   (this run used a local Postgres container: postgres:16 on :5433)
cp .env.example .env

# Run the DB migrations
.venv/bin/alembic upgrade head          # ✅ all 6 migrations applied cleanly

# ⚠ No seed script exists — create the first admin user yourself (see Problem #2),
#   e.g. via a one-off script using app.auth.get_password_hash('admin123!')

# ── Frontend ───────────────────────────────────────────────
cd ../school-frontend
# ⚠ `npm install` FAILS out of the box (ERESOLVE) — must use:
npm install --legacy-peer-deps
```

### 3.2 Start the servers
```bash
# Terminal 1 — backend (FastAPI) on :8000
cd school-backend
.venv/bin/uvicorn app.main:app --reload
# → API docs at http://localhost:8000/docs  (DEBUG=True)

# Terminal 2 — frontend (Vite dev server) on :5173
cd school-frontend
npm run dev
# → App at http://localhost:5173 (proxies /api → :8000)
```
Then open **http://localhost:5173** and log in with the admin user you created in 3.1.

### 3.3 Stop the servers
```bash
# Stop everything (works on any machine):
pkill -f "uvicorn app.main"; pkill -f "sh -c vite"; pkill -f "node.*vite"

# Or kill by port (whatever is listening):
fuser -k 8000/tcp    # backend
fuser -k 5173/tcp    # frontend

# Or kill by PID — current PIDs: backend 574189, frontend 574521/574522:
kill 574189              # backend
kill 574522 574521       # frontend

# Optional — stop the local Postgres container used in this run:
docker stop cgps-postgres
```

### 3.4 Check status / restart
```bash
# What is running?
pgrep -af "uvicorn app.main" && pgrep -af vite

# Health checks:
curl http://localhost:8000/health                        # → {"status":"healthy"}
curl -o /dev/null -w '%{http_code}\n' http://localhost:5173/   # → 200

# Restart = just re-run the two commands from section 3.2.
```

### 3.5 Production build (optional)
```bash
cd school-frontend
npm run build      # ✅ creates dist/ (with warnings)
npm run preview    # serve the production build locally
```

## 5. Problems found (why it does NOT run as-is)

### 🔴 P1 — Authentication is completely broken out of the box (bcrypt/passlib)
- `requirements.txt` pins `passlib[bcrypt]==1.7.4` but **not bcrypt** → pip installs latest bcrypt (≥4.1).
- `passlib 1.7.4` is unmaintained (2020) and breaks with bcrypt ≥4.1: it reads the removed `bcrypt.__about__.__version__` attribute **and** trips bcrypt's new 72-byte `ValueError` during its backend self-test.
- Result: **every `get_password_hash()` / `verify_password()` call raises → login and user registration can never succeed.**
- Verified on this run; fixed only inside the disposable venv with `pip install 'bcrypt==4.0.1'`.
- Proper fix (not applied): pin `bcrypt==4.0.1` in `requirements.txt`, or replace passlib with `bcrypt` directly (or use `argon2`).

### 🔴 P2 — No initial admin user and no seed script
- Nothing in the repo creates the first user, and the README documents no seed step → **a fresh install is locked out** (login impossible).
- The project's own test suite hard-codes `admin / admin123!` but nothing provisions that user.
- Workaround used here: inserted the admin row via the app's own `get_password_hash()` in a one-off script.
- Fix: add a seed script / a data migration that creates a first admin from env vars.

### 🔴 P3 — Frontend can't `npm install` (peer-dependency conflict)
- `package.json`: `vite: "^8.0.14"` vs `@vitejs/plugin-react: "^4.3.0"` (resolves to 4.7.0), which peer-depends on `vite ^4.2.0 || ^5 || ^6 || ^7`.
- `npm install` fails with `ERESOLVE`; only works with `npm install --legacy-peer-deps`.
- Even then, npm marks `vite@8.0.14` as **invalid** for plugin-react, and Vite 8 emits deprecations: `esbuild` option → use `oxc`, `optimizeDeps.rollupOptions` → `rolldownOptions`, plus a runtime "Invalid input options … Expected never but received 'jsx'" warning and a 674 kB single-chunk warning.
- Fix: bump to `@vitejs/plugin-react@^5` (or the new `@vitejs/plugin-react-oxc`) or downgrade `vite` to ^7.

### 🟡 P4 — Trailing-slash API mismatch (307 redirects) — 11/36 tests fail
- Collection routes are registered **with** trailing slashes (`POST /students/`, `/parents/`, `/teachers/`, `/fees`, …). Any call **without** the slash gets a Starlette **307 redirect**.
- The repo's own `scripts/test_all_api.py` POSTs **without** the slash → all 11 create tests report 307 (25/36 pass only because GETs use the slash). Its health/root checks (`/../health`) also resolve to `/api/v1/health` → 404 (endpoint itself is fine).
- The React frontend (`src/api.js`) also calls **without** trailing slashes and only works because axios silently follows redirects.
- Fix: pick one convention — register routes without trailing slash (`""` instead of `"/"`) and add `redirect_slashes=False`, or add `/` on the client side.

### 🟡 P5 — `.env` is hard-required at import time (no graceful fallback)
- `config.py` has no defaults for `DATABASE_URL`, `SYNC_DATABASE_URL`, `SECRET_KEY`, so importing **any** `app.*` module raises a pydantic `ValidationError` when env is missing. There is also no `.env` in the repo (only `.env.example`).
- RSA keys default to empty → CNIC create/update fails at runtime with `RSA_PRIVATE_KEY not configured` unless keys are generated and added to `.env` (documented in `.env.example`, easy to miss).
- Fix: provide defaults or a startup error message that is friendlier than a raw pydantic traceback.

### 🟢 P6 — Repo hygiene / doc drift (minor)
- `school-backend/cookies.txt` — empty curl cookie jar **committed to git**.
- Root `package-lock.json` with no root `package.json` (orphan artifact).
- `README.md` references a `school-frontend-html/` folder that **does not exist** in this repo.
- `school-frontend/index.html` links `/favicon.svg`, which doesn't exist (masked by Vite's SPA fallback).
- README says Alembic uses `SYNC_DATABASE_URL` (psycopg2) but `alembic/env.py` actually uses `DATABASE_URL` (asyncpg) — works, but docs are misleading.
- `models.py` imports `relationship` twice (second time aliased as `orm_relationship`) — harmless redundancy.
- Frontend `npm audit`: 7 vulnerabilities (3 moderate, 4 high) after forced install.
